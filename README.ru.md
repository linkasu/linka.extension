# Формат LINKa Extension (.linka)

> English version: [README.md](README.md)

## Назначение
`.linka` - это ZIP-архивы с карточными наборами для комплекса LINKa.look. В каждом файле лежит описание набора (`config.json`) и медиафайлы, которые используют карточки. Этот репозиторий описывает формат контейнера, чтобы внешние инструменты могли создавать, проверять и анализировать LINKa-наборы.

## Структура контейнера
- Файл является ZIP-архивом. `config.json` хранится в корне архива рядом с используемыми ресурсами.
- Пути в `config.json` - это имена ZIP entry, обычно простые имена файлов вроде `8f5a...png` или `speech.mp3`.
- Текущий редактор сохраняет новые или сгенерированные ресурсы под UUID-именами с исходным расширением.
- При объединении наборов, если имя ресурса уже занято, копируемый ресурс переименовывается в `uuid + расширение`, а ссылка в JSON обновляется.
- При сохранении LINKa.look удаляет неиспользуемые ресурсы и записывает свежий `config.json`.

```
primer.linka
├── config.json
├── 9f1d2c6e-7a5b-4d9e-8d2e-a5d1b4f32b11.png
└── 4cc5e8b9-7d7a-43fd-a97b-2b8a44ffb610.mp3
```

## Схема `config.json`
`config.json` - UTF-8 JSON. Текущий редактор LINKa.look пишет версию `"3.0"` и использует постраничную структуру.

| Поле | Тип | Обязательно | Описание |
| --- | --- | --- | --- |
| `version` | строка | да | Текущее значение - `"3.0"`. Прочитанные конфиги нормализуются к текущей версии при сохранении. |
| `withoutSpace` | bool | да | При `true` подписи карточек добавляются без автоматических пробелов, а `SpaceCard` может участвовать в выводе. |
| `directSet` | bool | нет (по умолчанию `false`) | Прячет строку вывода и сразу воспроизводит звук карточки. |
| `quizAutoNext` | bool | нет (по умолчанию `true`) | При правильном ответе в викторине автоматически переходит на следующую страницу. |
| `quizReadQuestion` | bool | нет (по умолчанию `false`) | Включает чтение вопроса викторины вслух, если проигрыватель это поддерживает. |
| `description` | строка | нет | Произвольное описание, отображаемое в диалоге LINKa.look. |
| `pages` | массив `SetPage` | да | Упорядоченные страницы набора. Это замена старой верхнеуровневой структуры `columns`, `rows`, `cards`. |

### Совместимость со старыми файлами
В старых файлах могут встречаться верхнеуровневые поля `columns`, `rows`, `cards`, `quiz` и `questions`. LINKa.look всё еще читает эти поля и переносит их в `pages`, но новые сохранения используют `version: "3.0"` со страницами.

## Страницы
Каждый элемент `pages` имеет такую структуру:

| Поле | Тип | Обязательно | Описание |
| --- | --- | --- | --- |
| `id` | строка | да | Идентификатор страницы. LINKa.look генерирует UUID-строки. |
| `mode` | enum-строка | да | `standard`, `quiz` или `match`. Некорректные или пустые значения нормализуются к `standard`. |
| `columns` | целое | да | Число колонок на странице. Значение нормализуется к целому `>= 1`. |
| `rows` | целое | да | Число строк на странице. Значение нормализуется к целому `>= 1`; для `match` всегда используется `2`. |
| `cards` | массив `Card` | да | Карточки в порядке строка-за-строкой. При чтении/сохранении страница обрезается или дополняется до `rows × columns`. |
| `question` | строка | для страниц `quiz` | Вопрос викторины. Для остальных режимов не сохраняется. |

### Режимы страниц
- `standard` - обычная страница коммуникативного набора.
- `quiz` - страница вопроса. Правильные ответы помечаются `card.answer: true`; `quizAutoNext` задает автоматический переход после правильного ответа.
- `match` - игра на сопоставление. Всегда две строки; пары связываются через `matchId`, а `matchLane` нормализуется в `top` или `bottom` по позиции карточки.

## Карточки
Поля отдельной карточки:

| Поле | Тип | Обязательно | Описание |
| --- | --- | --- | --- |
| `id` | строка | да | Идентификатор карточки. LINKa.look генерирует UUID-строки. |
| `cardType` | enum-целое | да | `0` = `AudioCard`, `1` = `SpaceCard`, `2` = `EmptyCard`, `3` = `NewCard`. |
| `width` | целое | нет (по умолчанию `1`) | Ширина карточки в ячейках сетки; значения <1 приводятся к 1. Поддерживается на страницах `standard` и `quiz`. |
| `height` | целое | нет (по умолчанию `1`) | Высота карточки в ячейках сетки; значения <1 приводятся к 1. Поддерживается на страницах `standard` и `quiz`. |
| `imagePath` | строка | для валидной `AudioCard` | Имя ZIP entry с изображением. Поддерживаются PNG, JPG, JPEG и GIF. |
| `title` | строка | для валидной `AudioCard` | Подпись карточки и текст для вывода. |
| `audioPath` | строка | нет | Имя ZIP entry с аудиофайлом. Поддерживаются MP3, WAV и OGG. |
| `audioText` | строка | нет | Текст, из которого была сгенерирована озвучка карточки. |
| `audioVoice` | строка | нет | Идентификатор голоса для `audioText`, если он есть. |
| `answer` | `true` | для правильных ответов в `quiz` | Имеет смысл только на страницах `quiz`. При нормализации удаляется с остальных страниц. |
| `matchId` | строка | для пар в `match` | Общий идентификатор двух `AudioCard`, которые образуют пару. Удаляется с не-`match` страниц. |
| `matchLane` | `top` или `bottom` | генерируется для `match` | Нормализуется по позиции карточки. Удаляется с не-`match` страниц. |

### Типы карточек
- `AudioCard (0)` - обычная карточка с изображением, подписью и опциональным звуком. В редакторе валидна только при наличии `imagePath` и `title`.
- `SpaceCard (1)` - карточка пробела. Участвует в выводе при `withoutSpace = true`.
- `EmptyCard (2)` - сохраненная пустая заглушка, которая удерживает форму сетки.
- `NewCard (3)` - редакторская заглушка для пустой редактируемой ячейки. При сохранении набора превращается в `EmptyCard`.

## Логические флаги
- `withoutSpace` управляет сборкой текста. При `true` LINKa.look добавляет вывод `AudioCard` и `SpaceCard` подряд. При `false` в стандартном режиме добавляется только вывод `AudioCard`.
- `directSet` нужен для наборов, которые должны звучать сразу. Он прячет строку вывода и принудительно включает воспроизведение звука карточки.
- `quizAutoNext` задает автоматический переход после правильного ответа в викторине.
- `quizReadQuestion` хранит настройку чтения вопросов викторины вслух в поддерживаемых проигрывателях.

Карточка с `width` или `height` больше `1` занимает прямоугольник из нескольких ячеек, начиная со своей позиции в порядке обхода строка-за-строкой. Покрытые позиции в `cards` нужно заполнять `EmptyCard`, чтобы старые версии приложений, которые игнорируют `width`/`height`, безопасно показали набор как обычную сетку `1×1` без падения. Если объединённая карточка не помещается до края страницы, загрузчик вправе уменьшить её размер до доступного пространства.

## Ресурсы
- Изображения: поддерживаются PNG, JPG, JPEG и GIF.
- Аудио: принимаются MP3, WAV и OGG. Сгенерированная text-to-speech озвучка сохраняется как MP3.
- При сохранении остаются только ресурсы, на которые ссылаются `AudioCard.imagePath` и `AudioCard.audioPath`.
- Пользовательские имена файлов должны быть безопасны для ZIP и уникальны. Имена, созданные LINKa.look, основаны на UUID.

## Пример `config.json`
```json
{
  "version": "3.0",
  "withoutSpace": false,
  "directSet": false,
  "quizAutoNext": true,
  "quizReadQuestion": false,
  "description": "Пример продуктового набора",
  "pages": [
    {
      "id": "b1f93341-7a7e-46df-b928-d49f9eecb57d",
      "mode": "standard",
      "columns": 3,
      "rows": 2,
      "cards": [
        {
          "id": "f4926d55-477f-4900-b016-3298b17b30ea",
          "cardType": 0,
          "width": 2,
          "imagePath": "yabloko.png",
          "title": "Яблоко",
          "audioPath": "yabloko.mp3"
        },
        {
          "id": "1aa5db1a-48f5-47d5-bcb4-9da5d5c54723",
          "cardType": 2
        },
        {
          "id": "8c299d04-cb51-4dbf-946f-ad5177535a47",
          "cardType": 1
        }
      ]
    }
  ]
}
```

## Чек-лист валидации
1. Убедитесь, что файл открывается как ZIP, а `config.json` лежит в корне.
2. Прочитайте `config.json` как UTF-8 JSON и проверьте/нормализуйте структуру по схеме выше.
3. Убедитесь, что каждая ссылка `AudioCard.imagePath` и `AudioCard.audioPath` существует в архиве.
4. Проверьте размеры страниц и убедитесь, что до нормализации карточек не больше, чем `rows × columns`.
5. Для страниц `quiz` проверьте, что хотя бы один ожидаемый правильный ответ имеет `answer: true`.
6. Для страниц `match` проверьте, что каждый `matchId` связывает ровно две `AudioCard` в разных строках.
7. Протестируйте набор в LINKa.look: обычный вывод, викторину, сопоставление и прямое воспроизведение.
